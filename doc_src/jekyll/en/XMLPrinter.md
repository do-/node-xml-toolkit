# Generating Well Formed XML with XMLPrinter

* toc
{:toc}

As XML is totally human readable and hand writable, you generally don't need any specialized tool to produce it. Especially with ES6 text templates, you just take a sample and put in some placeholders:

~~~js
  const xml = ```xml
    <request>
      <param name="${param.name}">${param.value}</param>
    </request>
  ```
~~~

It works well until one of those pesky `'<&>"` characters occurs. At that point, you have three basic options:
* resort to calling [`replace`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/replace) / [`replaceAll`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String/replaceAll) for every string to interpolate (`RegExp`s slow down things by the way, even precompiled ones);
* start an (N+1)th XML serialization library micro project;
* use an existing one.

If you are at the square #3, consider `node-xml-toolkit`'s 
* `XMLPrinter` (for limited size documents) and 
* `XMLStreamPrinter` (for large files) 

which work around most pitfalls and offer some configuration options for the case you want not just a well formed, but pretty printed XML.

> **Note**: If you have an XML Schema your output must comply with, skip this charter and go ahead to the next one, about `XMLMarshaller`.

## Configuration

Both printers accept the same constructor parameters. All are optional:

| Option | Default | Description |
|--------|---------|-------------|
| `decl` | `undefined` | If set, automatically writes an XML declaration (`<?xml ...?>`) with the provided `encoding` and `standalone` values |
| `space` | `undefined` | Indentation for pretty-printing. Accepts a string (e.g., `'\t'`) or a number (repeated spaces, e.g., `2` → `'  '`). If unset, output is minified (single-line) |
| `attrSpace` | `undefined` | Additional indentation for attributes. When set, each attribute appears on its own line, indented relative to the opening tag |
| `EOL` | [`os.EOL`](https://nodejs.org/docs/latest/api/os.html#oseol) | Line ending string. Only relevant when `space` is set |
| `level` | `0` | Initial indentation level (number of `space` units to prepend) |
| `encodeLineBreaks` | `true` | When `true`, replaces `\n` and `\r` in text/attributes with numeric entities (`&#10;`, `&#13;`)|

### Example: Pretty-printed output with custom indentation

```javascript
const {XMLPrinter} = require('xml-toolkit');

const xp = new XMLPrinter({
  space: 2,              // 2-space indentation
  attrSpace: '  ',       // Attributes on new lines, indented 2 extra spaces
  decl: { encoding: 'UTF-8' } // Auto-write XML declaration
});
```

## API Methods

Both printers expose the same chainable methods. Each returns `this` to enable fluent composition.

### writeXMLDecl

Writes an [XML declaration](https://www.w3.org/TR/xml/#sec-prolog-dtd). Must be called before any elements. The `standalone` value is normalized: truthy → `'yes'`, falsy → `'no'`.

```javascript
xp.writeXMLDecl({ encoding: 'UTF-8', standalone: 1 });
// Output: <?xml version="1.0" encoding="UTF-8" standalone="yes"?>
```

### openElement

Begins an element: writes `<${name}` and marks the tag as "open" for attribute appending. Pushes `name` onto the internal stack.

> **Note**: In the spirit of perfectly pure [XML 1.0](https://www.w3.org/TR/xml/) (thus [without any idea about namespaces](http://www.jclark.com/xml/xmlns.htm)), the low-level API treats element/attribute names as opaque strings and NS declarations as attributes.

### writeAttribute

Appends an attribute to the currently open element. Both `name` and `value` must be strings. Values are automatically escaped for XML attribute context.

```javascript
xp.openElement('my:item')
  .writeAttribute('xmlns:my', 'http://tempuri.org') // NS prefixes: DIY
  .writeAttribute('id', '123')
// Output: <my:item xmlns:my="http://tempuri.org" id="123"
```

### writeCharacters

Writes text content with automatic escaping for XML character data (`<`, `>`, `&`, `"`, and—optionally—line breaks).

```javascript
xp.writeCharacters('5 < 10 && 3 > 1');
// Output: 5 &lt; 10 &amp;&amp; 3 &gt; 1
```

### writeBody

Writes raw XML content *without* escaping. Use only when `value` is a pre-validated, well-formed XML fragment (e.g., for embedding `xs:any` content). Throws if called outside an element context.

```javascript
xp
  .openElement('envelope')
    .writeBody ('<request id="1" param2="3"/>')
  .closeElement()
// <envelope><request id="1" param2="3"/></envelope>
```

### writeNode

For cases where you already have a structured representation generated by `XMLParser` or `XMLReader`, `writeNode` recursively serializes an `XMLNode` object:

```javascript
xp
  .openElement('envelope')
    .writeNode((new XMLParser()).process ('<request id="1" param2="3"/>'));
  .closeElement()
// <envelope><request id="1" param2="3"/></envelope>
```

It's used internally by [XMLNode.toString ()](../XMLNode/#tostring).

### closeElement

Closes the most recently opened element. If no content was added, emits a self-closing tag (`<name />`); otherwise, emits `</name>`. Pops the element name from the internal stack.

## Varieties

### In-Memory `XMLPrinter`

`XMLPrinter` accumulates output in the `.text` property. 

At any moment, it can be reinitialized by calling `.reset()` to be used again.

```javascript
const {XMLPrinter} = require('xml-toolkit');

const xp = new XMLPrinter({ space: 2 });

const xml = xp
  .openElement('catalog')
    .writeAttribute('updated', '2026-04-24')
    .openElement('product')
      .writeAttribute('id', 'p1')
      .openElement('name')
        .writeCharacters('Widget')
      .closeElement()
      .openElement('price')
        .writeCharacters('19.99')
      .closeElement()
    .closeElement()
  .closeElement()
  .text;

console.log(xml);

xp.reset(); // Cleaned up, may be used again
xp.writeXMLDecl({ encoding: 'UTF-8', standalone: 1 }); 
  // ...etc next document
```

### Streaming `XMLStreamPrinter`

`XMLStreamPrinter` writes directly to a Node.js `Writable` stream supplied via constructor. It does not expose the partial content and can't be reinitialized/reused.

```javascript
const fs = require('node:fs');
const {XMLStreamPrinter} = require('xml-toolkit');

const out = fs.createWriteStream('output.xml');
const xp = new XMLStreamPrinter({ out, space: 2 });

xp
  .openElement('report')
    .openElement('summary')
      .writeCharacters('Q1 2026 results')
    .closeElement()
  .closeElement();

out.end(); // Finalizes the stream
```
